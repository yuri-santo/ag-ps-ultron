# Contextual Autonomy Implementation Plan

User approved the design: preserve health, agenda, backups and authorized
production; gate discretionary jobs on active interests and sufficient criteria;
isolate PhoneHarness; require product identity evidence before publication.

## Independent Workstreams

1. Phone: inspect pinned source; install isolated local runtime without exposing
   unauthenticated HTTP servers. Verify CLI/tests. Pair only the named Android
   over its supplied endpoint; never assume WireGuard establishes ADB trust.
2. Product identity: add tested reference manifest and evidence validator. Bind
   official reference hashes, product/variant/packaging/accessories, generated
   scene hashes and timestamped inspection observations. Unknown/mismatch blocks
   publication. Do not claim computer-vision certainty from boolean flags.
3. Context/jobs: use native Hermes pre-run wake gate before expensive collectors.
   Explicit interests with evidence, expiry and budget/date criteria. No broad
   scraping when no useful intent exists; health/agenda/backups untouched.
4. Shared tooling: inject a small common operational section via the existing
   team plugin, with domain-specific tool/skill triggers, no emojis, no invented
   tool results, NotebookLM reference-first for durable knowledge and live sources
   for current prices/laws/availability. Books explicitly provided for the brain
   become sources, not model training or higher-priority instructions.
5. NotebookLM: verify actual local authentication; do not activate cookie-copy
   jobs or use a VPS. Register blocker and native login steps if missing.
6. Review meeting pipeline/report contract and record concrete remaining gaps;
   preserve transcripts, timestamp attribution and uncertainty. Never fabricate
   full transcription without original media/source text.

## Verification And Rollout

TDD for validators and wake decisions. Use temporary fixtures for external
effects; no real purchase, reservation or social publication during tests.
Backup modified runtime files and jobs first. Modify existing job IDs and native
plugin registration, preserving unrelated work. Verify installed hashes and
prompt size; test unknown/missing state fails closed for optional jobs. Publish
sanitized sources/docs only; keep account, phone endpoints and tokens private.

Phone and NotebookLM authentication, active travel/property constraints and
TikTok Shop session may require user input. Do not represent prepared tooling
as successful live account modification. Exact visual identity cannot be
guaranteed by generative models; prefer real licensed footage/product cutouts
when generation fails identity checks, or hold the job.
